## Why

High Signal now has an evidence-qualified public corpus, but its current search
footprint mostly exposes individual records without clear entry pages for the
questions people use to discover the product. The latest 28-day Search Console
baseline contains only six impressions and no clicks, so adding more generated
records would not solve the discovery problem.

## What Changes

- Add four public intent pages for the Daily Brief, startup intelligence,
  founder market-intelligence workflow, and technology-trend intelligence.
- Expand the existing `/agent-eval/seo` tool with an accurate explanation of
  technical readiness versus observed AI awareness.
- Implement the editorial surfaces through one typed content registry and one
  reusable reading component while keeping explicit canonical routes.
- Register every surface in the canonical sitemap, agent catalog, Markdown
  alternate behavior, and contextual internal-link graph.
- Preserve the qualified public-corpus policy and the locked High Signal visual
  and product direction.

## Capabilities

### New Capabilities

- `intelligence-content-cluster`: Defines the public intent surfaces, their
  evidence boundaries, discovery wiring, and internal path into product proof.

### Modified Capabilities

- `public-intelligence-corpus`: Adds four qualified static entry routes without
  changing any dynamic-route evidence threshold.

## Impact

- Affects the web content registry, four explicit page routes, the existing SEO
  and GEO audit page, public route registry, agent index, home/explore links,
  structured data helpers, and durable project status.
- Adds no dependency, database migration, API behavior, or new product wedge.
- Production deployment and search submission remain separately gated actions.
